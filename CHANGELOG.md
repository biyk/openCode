# CHANGELOG — голосовой ассистент

Правила работы:
- Каждый этап всегда даёт **работающее приложение** с новыми фишками.
- Каждая новая фишка — **за feature-флагом** (по умолчанию выключена). Если что-то сломалось — выключаем флаг, и приложение работает как раньше.
- После каждого этапа пользователь **сам проверяет функционал** и пишет ответ: лучше / хуже / сломалось / работает не так.
- Формат ответа пользователя по каждому пункту «Что проверить»: `+` (работает), `-` (сломано), `~` (работает не так).

## П2.2 — Надёжный детектор стоп-слов + фикс WinError 32 (2026-09-12)

**Баг:** при длинной громкой озвучке диктовочная модель Vosk «тонула» в аудио TTS и не сегментировала слово «стоп» — прервать озвучку было невозможно (пришлось перезапускать программу).

### Что нового
- **Грамматический распознаватель стоп-слов**: помимо основной диктовки, отдельный `KaldiRecognizer` с грамматикой из стоп-слов (`стоп/останови/stop/хватит/прекрати`) следит за микрофоном всё время озвучки и ловит «стоп» даже на фоне голоса ассистента.
- **Фикс ошибки WinError 32**: при прерывании плеер mpg123 успевал закрыться, а удаление временного mp3 падало с «файл занят» — теперь такие удаления безопасно игнорируются.

### Что проверить
1. Задай длинный вопрос LLM (чтобы озвучка шла долго) → во время озвучки скажи «**стоп**» → обрыв сразу.
2. Сразу после — «**пожалуйста, сделай тише**» → работает чисто.
3. В консоли НЕТ строки `[ERROR] Ошибка озвучки: [WinError 32]...`.
4. Команды и поведение без озвучки не задето.

## П2 — Интеллектуальный классификатор команд (intent) + файловый лог сеанса (2026-09-12)

**Флаг:** `intent.enabled` (и `intent.include_media`) в `targets/<host>/commands.json`. По умолчанию ВЫКЛЮЧЕН; на этой машине ВКЛЮЧЕН.

### Что нового
- Вместо слова «мини» и fuzzy-матча — **LLM-классификатор намерений** (`lib/intent.py`): команда, не найденная дословно, отправляется в омни-роутер, и тот выбирает id из доступного списка команд или отвечает `NONE`.
- Распознанная команда **исполняется**, LLM-диалог при этом не запускается. Нет соответствия / ответ не является командой → обычный LLM-ответ.
- **Флаг медиа** (`lib/media.py` + `bin/media_state.ps1`): классификатору подсказывается, играет ли сейчас музыка/видео — команды вроде «громче/тише/плей» без воспроизведения не принимаются (`NONE`).
- «сделай кромку пожалуйста» → `volumeup` (исполняется); «сделай поппу пожалуйста» → НЕ громче, уходит в обычный LLM-диалог.
- **Файловый лог сеанса**: всё из консоли + отладочные детали пишутся в один файл `logs/ГГГГММДДЧЧММ.log` на каждый запуск (например `logs/202609121456.log`). В консоли — кратко, в файле — подробно (`[DEBUG]`, `[LLM] Ответ: ...`). Папка `logs/` в корне проекта.

### Что проверить
1. «**пожалуйста, сделай кромку**» → громкость меняется, запросов к LLM-диалогу нет.
2. «**пожалуйста, сделай поппу**» → громкость НЕ меняется, ассистент отвечает через LLM (обычный диалог).
3. Когда медиа НЕ играет (музыка на паузе/нет музыки) → «пожалуйста, плей/громче» не должны давать ложной команды.
4. Задай вопрос LLM — в свежем файле `logs/<по времени>.log` есть строка `[DEBUG] [LLM] Ответ: ...`.
5. Обычные команды и «стоп» во время озвучки работают как раньше.

## П2.1 — Детальное логирование LLM-решений и консольный UX (2026-09-12)

### Что нового
- **Консоль**: после распознанного текста с триггером, если команда не найдена, выводится «... отправка запроса LLM» — пользователь видит, что ушло в LLM.
- **Лог (`logs/...log`)**: подробная диагностика решения:
  - `[LLM Decision] Trigger found, no command match, no intent match. Sending to LLM. Text: ...` — почему ушло в LLM.
  - `[LLM Request] model=auto, messages=[...]` — полный промпт, ушедший в омни-роутер.
  - `[LLM Response] ...` — ответ модели.
  - `[LLM Error] ...` — ошибки запроса.
- В консоль кратко (`print_info`/`print_text`), в лог подробно (`print_debug` + существующие `print_*`).

### Что проверить
1. Скажи **«пожалуйста, расскажи анекдот»** (триггер есть, команды нет) → в консоли после текста появится `... отправка запроса LLM`, затем озвучка ответа.
2. Открой свежий `logs/...log` → там есть `[LLM Decision]...`, `[LLM Request] model=auto, messages=[...]`, `[LLM Response] ...`.
3. Ошибка LLM (остановить омни-роутер) → в логе `[LLM Error] ...`, в консоли сообщение об ошибке.
4. Обычные команды и стоп-слово работают как раньше.

## П2.2 — Исправление кодировки логов (Windows) (2026-09-12)

### Проблема
Vosk на Windows возвращает текст в неверной кодировке (cp866 вместо utf-8) — в логах и консоли появляется мусор вместо распознанного текста.

### Решение
- При старте на Windows выполняется `chcp 65001` и переконфигурация stdout/stderr в UTF-8.
- Добавлена функция `_fix_encoding(text)` — пытается перекодировать текст из cp866 в utf-8 (с graceful fallback).
- Функция применяется ко всем результатам Vosk (финальные, частичные, стоп-распознаватель).

### Что проверить
1. Распознанный текст в консоли и логах читаем (нет мусора/кракозябр).
2. Стоп-слово во время озвучки работает.
3. Команды работают как раньше.

## П1.1 — Исправление: стоп-слово во время озвучки (2026-09-12)

**Баг:** при длинной озвучке сказать «стоп» не получалось — микрофон слышит голос ассистента из колонок, Vosk не выдаёт «стоп» отдельным финальным результатом (слово тонет в общем буфере).

**Фикс:** стоп-слово теперь отслеживается и по **частичным** результатам распознавания (`PartialResult`) — прерывание срабатывает, пока слово ещё досказано, даже если финального результата Vosk не дал. После прерывания распознаватель сбрасывается (`Reset`), команды после этого распознаются чисто.

### Что проверить
1. Задай длинный вопрос LLM, во время озвучки скажи «**стоп**» → озвучка обрывается сразу.
2. Сразу после «стоп» скажи «**пожалуйста, сделай тише**» → команда выполняется (распознавание не «запачкано» эхом озвучки).

## Базовый функционал (зафиксировано, коммиты bb9b097, 77a759c)

### Активные фичи
- **Триггерные слова** «пожалуйста» / «алиса» — команды выполняются только с триггером, иначе текст печатается в консоль.
- **Голосовые команды** (настраиваются в `targets/<host>/commands.json`): громкость, пауза/плей.
- **Озвучка ответов LLM** голосом (gTTS → Piper → Windows SAPI в порядке убывания приоритета).
- **Стоп-слово во время озвучки**: работает только {"стоп", "останови", "stop", "хватит", "прекрати"} — прерывает и воспроизведение, и синтез. Запись микрофона при этом не останавливается.
- **Эхо-затишье** 0.5с после озвучки, чтобы последний слог TTS не сработал как команда.
- Модель провайдера **omni**: `auto` (роутер сам выбирает).
- Тесты: 100% покрытие (239 passed на тот момент).
